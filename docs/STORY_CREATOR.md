# Story Creator

## Overview

The weekly bilingual story is **generated by this script** through the external
**StoryCreator public API** (`https://bilingualstory.net`). Each `--generate` run creates
one story per learner pair (`--languages fr en` → native French + native English, both
learning European Portuguese), waits for the AI writer to finish, and stores each one as
a language template in `weeklystory_templates`. Per-user documents in `weeklystories`
then point at the template matching the user's `preferredLanguage`.

Read modes (fetch/list) need only the `stories:read` scope; `--generate` needs
`stories:write` plus an OpenAI key for the idea agent.

| File | Purpose | DB required? |
|------|---------|--------------|
| `story_writter/StoryCreatorGetter.py` | Generates or fetches stories through the StoryCreator API and upserts `weeklystory_templates` / links `weeklystories`. | ✅ for storage |
| `story_writter/test_story_creator_getter.py` | Unit tests (no network, in-memory collections). | ❌ |

## Architecture

```
StoryCreatorGetter.py
  ├── generate_story_idea(...)         ← OpenAI agent invents title/theme/seed/cast
  ├── build_story_payload(...)         ← POST /api/v1/stories body
  ├── create_story(...)                ← POST /api/v1/stories (stories:write)
  ├── wait_for_story(...)              ← polls GET /api/v1/stories/:id until ready
  ├── to_app_story(...)                ← converts lang1/lang2 → pt + native schema
  ├── upsert_story_template(...)       ← weeklystory_templates, one per {weekStart, language}
  ├── link_user_story(...)             ← weeklystories, one per {userId, weekStart} + templateId
  └── (read modes) list_stories / find_latest_story / fetch_story
```

A story that is still generating is polled until it is ready (or `failed`), so a
scheduled run never stores a half-written story.

### Collections

| Collection | Document | Purpose |
|---|---|---|
| `weeklystory_templates` | one per `{weekStart, language}` (`fr`, `en`) | The generated story for the week |
| `weeklystories` | one per `{userId, weekStart}` with `templateId` + `language` | Per-user link (guests get a clone lazily from the API) |

`GET /api/weekly-story` resolves the user's document, creates it from the
language-matched template on first access, and returns the template's `story`. There is
no shared `userId: null` document anymore.

## Setup

**Requirements:** Python 3.10+, `httpx`, `pymongo`, plus `openai-agents` / `openai` for
`--generate`.

```bash
pip install -r story_writter/requirements.txt
```

**Environment variables:**

| Variable | Required by | Description |
|----------|------------|-------------|
| `STORYCREATOR_API_KEY` | all runs | API key; `stories:read` for read modes, `stories:write` for `--generate` |
| `STORYCREATOR_API_URL` | all runs | Base URL (default `http://localhost:3000`) |
| `MONGODB_URI` | storage | MongoDB Atlas connection string |
| `OPEN_AI_KEY` | `--generate` | OpenAI key for the idea agent (`OPENAI_API_KEY` also accepted) |
| `STORYCREATOR_IDEMPOTENCY_KEY` | `--generate` (optional) | Base retry key; the language is appended. Defaults to a per-week key |
| `STORYCREATOR_STORY_ID` | fetch mode | Explicit story id; overrides the automatic lookup |
| `STORYCREATOR_AUTHOR` | list mode | Default `--author` filter when none is passed |

## Local Development

```bash
cd story_writter
export STORYCREATOR_API_KEY="stc_live_..."
export STORYCREATOR_API_URL="https://bilingualstory.net"
export OPEN_AI_KEY="sk-..."

# Print the two ideas + requests without calling the API
python StoryCreatorGetter.py --generate --dry-run

# Generate both pairs and store them as this week's templates
python StoryCreatorGetter.py --generate

# Regenerate a single pair, overwriting the existing template
python StoryCreatorGetter.py --generate --languages fr --force

# Link every registered user to their language's template
python StoryCreatorGetter.py --all-users

# Read the newest existing story created through the DialectHubWrite API key
python StoryCreatorGetter.py

# Read a specific story / list the catalogue
python StoryCreatorGetter.py 6ad3da2d233a762967c9e718
python StoryCreatorGetter.py --list --author charly --limit 50

# Store a fetched story as a template for its native language
python StoryCreatorGetter.py 6ad3da2d233a762967c9e718 --save-to-mongo
```

### CLI flags

| Flag | Default | Description |
|------|---------|-------------|
| `--generate` | `False` | Create stories via `POST /api/v1/stories` (needs `stories:write` + `OPEN_AI_KEY`) |
| `--languages` | `fr en` | Learner pairs (native languages) to generate; the learning side is `--learning-language` |
| `--force` | `False` | Regenerate even when the week already has a template for the language |
| `--dry-run` | `False` | Generate the ideas and print the requests without calling the API |
| `--level` | `beginner` | `beginner`, `intermediate` or `advanced` |
| `--learning-language` | `pt` | Language being learned |
| `--learning-language-name` | `European Portuguese` | Human-readable name used in the seed prompt |
| `--theme` | _random_ | Fixed theme (a random one is picked per language otherwise) |
| `--chapters` | `3` | Chapters per story (1-10) |
| `--sentences-per-chapter` | `8` | Target sentences per chapter (1-100) |
| `--idea-model` | `gpt-4.1-mini` | OpenAI model used by the idea agent |
| `--ai-model` | _server default_ | Model used by the server to write the story |
| `--no-publish` | `False` | Create a draft instead of publishing |
| `--idempotency-key` | per week | Base `Idempotency-Key`; the language is appended |
| `story_id` | _newest API story_ | Existing story id to fetch (read mode) |
| `--list` | `False` | List stories via `GET /api/v1/stories?limit=&page=&author=` |
| `--limit` / `--page` | `20` / `1` | Pagination for `--list` |
| `--author` | `$STORYCREATOR_AUTHOR` | Only list stories by this author |
| `--source` / `--api-key-name` | `api` / `DialectHubWrite` | Provenance filter for the newest-story lookup |
| `--generation-timeout` | `900` | Max seconds to wait for a story to be ready |
| `--poll-interval` | `5` | Seconds between status polls |
| `--save-to-mongo` | `False` | Upsert a fetched story into `weeklystory_templates` |
| `--all-users` | — | Link every registered (non-guest) user to their language template |
| `--user-id` / `--username` | — | Link one user instead |
| `--format` | `text` | `text` (parallel text) or `json` printout |
| `--output` | _(empty)_ | Write the idea/request/story as JSON (one file per language) |
| `--timeout` | `60` | HTTP request timeout in seconds |

## Production / Website

The weekly CronJob generates both templates and links every registered user:

```bash
cd story_writter
export STORYCREATOR_API_KEY="stc_live_..."   # stories:write
export STORYCREATOR_API_URL="https://bilingualstory.net"
export OPEN_AI_KEY="sk-..."
export MONGODB_URI="mongodb+srv://..."

# Generate fr + en templates for this week, then link every user
python StoryCreatorGetter.py --generate --all-users

# One user only
python StoryCreatorGetter.py --username alice
```

- A language that already has a template for the week is skipped; `--force` regenerates it.
- `STORYCREATOR_IDEMPOTENCY_KEY` (set from the Job name in Helm) protects a pod retry.
- Guests are not written by this script: `GET /api/weekly-story` clones the template for
  them on first access.

## Idea / Seed

`--generate` sends a seed to the API. An OpenAI agent invents the theme, cast, vocabulary
and premise; the script appends the vocabulary list and the level instruction. Read modes
never send a seed.

## Story Object Schema

Stories are stored under `weeklystory_templates.story`:

```json
{
    "id":           "<StoryCreator story id>",
    "language":     "fr | en",
    "title_pt":     "<Portuguese title>",
    "title_native": "<French or English title>",
    "title_fr":     "<legacy alias of title_native>",
    "level":        "beginner | intermediate | advanced",
    "topic":        "<short topic label>",
    "sentences": [
        {"pt": "<European Portuguese sentence>", "native": "<translation>", "fr": "<legacy alias>"}
    ],
    "created_at":   "YYYY-MM-DD",
    "source":       "storycreator-api"
}
```

The API's `learningLanguage` side becomes `pt`; the `nativeLanguage` side becomes `native`
(plus the legacy `fr` key). The website renders `title_fr ?? title_native` and
`sentence.fr ?? sentence.native`. A story without a `level` logs an error and stores
`beginner`.

## Automatic story selection

Read modes keep the previous behaviour: when no story id is passed, the script lists the
catalogue (`GET /api/v1/stories?limit=50&page=1`) and keeps only stories with:

```json
{"creationSource": "api", "createdViaApiKeyName": "DialectHubWrite"}
```

It then fetches the most recent one (by `createdAt`). Override the filters with
`--source` / `--api-key-name`, or skip the lookup by passing an id
(`python StoryCreatorGetter.py <id>` or `STORYCREATOR_STORY_ID`).

### Execution log

Read modes log every candidate and the final choice, so the selection is auditable:

```
INFO  No story id given — looking up the newest story (creationSource=api, createdViaApiKeyName=DialectHubWrite)
INFO  Candidate 1/4: id=web-1 | creationSource='website' -> SKIPPED (creationSource 'website' != 'api')
INFO  Candidate 2/4: id=new-api -> MATCH (newest so far)
INFO  --- Story selection summary ---
INFO  Selected story id   : new-api
INFO  Using newest DialectHubWrite story: new-api
```

`--generate` logs the idea (title, theme, vocabulary, seed), the idempotency key, the
queued story id and the final sentence count per language.

## Kubernetes CronJob

`helm/portuguese-learning/templates/weekly-story-cronjob.yaml` runs
`StoryCreatorGetter.py --generate --all-users --languages <values.weeklyStory.languages>`
in the analytics image every Monday at 05:00. It injects `MONGODB_URI`,
`STORYCREATOR_API_KEY`, `OPEN_AI_KEY` and `STORYCREATOR_IDEMPOTENCY_KEY` (from the Job
name) from the `portuguese-learning-secrets` Secret, plus `STORYCREATOR_API_URL` from
`weeklyStory.apiUrl`.

> **Required secrets:** `storycreator-api-key` (write scope) and `open-ai-key`.

Schedule, languages and resource limits are configured in `values.yaml` under
`weeklyStory`.

## Tests

```bash
python3 story_writter/test_story_creator_getter.py -v
```

Covers payload building, idea normalisation, idempotency keys, the `pt`/`native` schema
mapping, template upsert/lookup and user linking — in-memory collections, no network.
